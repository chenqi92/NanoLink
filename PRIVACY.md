# NanoOps Privacy Policy

Effective date: August 11, 2026

NanoOps is the mobile client for the open-source NanoOps ecosystem. It connects directly to NanoOps Server instances chosen and operated by the user or the user's organization.

## Data collection

The NanoOps project and its developers do not collect, sell, rent, track, or use personal data from NanoOps. The app contains no advertising SDK, analytics SDK, cross-app tracking, or developer-operated crash reporting service.

## Data stored on the device

NanoOps stores server addresses, display preferences, and connection metadata on the device. Authentication tokens and saved credentials are stored using the operating system's secure storage. This local data can be removed by deleting the related server connection or uninstalling the app.

## Connections to self-hosted servers

NanoOps sends authentication requests, commands, and other user-initiated requests directly to the NanoOps Server configured by the user. It receives server status, infrastructure metrics, alerts, audit records, logs, and command results from that server. The NanoOps project and its developers do not operate, receive, or retain this traffic.

The operator of each configured NanoOps Server controls its accounts, retention, access policies, and server-side data. Users should review the privacy and security practices of their server operator.

## Device permissions

- Local network access lets NanoOps connect to NanoOps Server instances on the user's network.
- Camera access is used only when the user chooses to scan a pairing QR code.
- Notification permission is used to show locally generated server-health alerts selected by the user.

## Third-party services

NanoOps does not send data to advertising, analytics, or tracking providers. Opening source code, documentation, support, or bug-report links may open GitHub in the user's browser, where GitHub's own privacy policy applies.

## Security

NanoOps supports TLS connections and secure credential storage. Users are responsible for operating their self-hosted NanoOps Server securely, configuring appropriate access controls, and protecting their server credentials.

## Changes and contact

Material changes to this policy will be published in this repository. Privacy questions and bug reports can be submitted through [NanoOps Issues](https://github.com/chenqi92/NanoLink/issues).

# NanoOps 隐私政策

生效日期：2026 年 8 月 11 日

NanoOps 是开源 NanoOps 生态的移动客户端，会直接连接到由用户或其所属组织选择并运营的 NanoOps Server。

## 数据收集

NanoOps 项目及其开发者不会通过 NanoOps 收集、出售、出租、跟踪或使用个人数据。应用不包含广告 SDK、分析 SDK、跨应用跟踪功能或由开发者运营的崩溃上报服务。

## 设备本地存储

NanoOps 会在设备本地保存服务器地址、显示偏好和连接元数据。认证 Token 与已保存的凭据通过操作系统的安全存储保存。用户可以删除对应的服务器连接或卸载应用来移除这些本地数据。

## 连接自托管服务器

NanoOps 会把认证请求、命令和其他由用户发起的请求直接发送到用户配置的 NanoOps Server，并从该服务器接收服务器状态、基础设施指标、告警、审计记录、日志和命令结果。NanoOps 项目及其开发者不会运营、接收或留存这些通信内容。

每个 NanoOps Server 的运营者负责其账号、数据保留、访问策略和服务端数据。用户应了解其服务器运营者的隐私与安全规则。

## 设备权限

- 本地网络权限仅用于连接用户网络中的 NanoOps Server。
- 相机权限仅在用户主动扫描配对二维码时使用。
- 通知权限仅用于展示用户选择的、由设备本地生成的服务器健康告警。

## 第三方服务

NanoOps 不会向广告、分析或跟踪服务商发送数据。用户打开源代码、文档、支持或 Bug 反馈链接时，应用可能在浏览器中打开 GitHub，此时适用 GitHub 自身的隐私政策。

## 安全

NanoOps 支持 TLS 连接和安全凭据存储。用户有责任安全运营其自托管的 NanoOps Server、配置合适的访问控制并妥善保护服务器凭据。

## 政策变更与联系

本政策的重要变更会在本仓库中公布。如有隐私问题或 Bug，可通过 [NanoOps Issues](https://github.com/chenqi92/NanoLink/issues) 提交。
